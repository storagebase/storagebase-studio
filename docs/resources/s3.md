# Amazon S3 provider (`s3`)

## Connection

`region` or an S3-compatible `endpoint` override (one is required), plus
`accessKeyId` / `secretAccessKey` and an optional `sessionToken` for STS.
Anonymous buckets are not refused at validate time — there is no reliable
 typeless probe for "public", so the server answers instead.

The endpoint override forces path style. That is the whole wire-relative
mechanism: MinIO, R2, Spaces and DigitalOcean connect through this type-id,
never their own.

## Wire relatives

| Endpoint | Override value | Notes |
|---|---|---|
| MinIO (self-hosted) | `http://localhost:9000` | Fixture in `resources-compose.yml`; console on `:9001` |
| Cloudflare R2 | `https://<account-id>.r2.cloudflarestorage.com` | Path style forced, same as MinIO |
| DigitalOcean Spaces | `https://<region>.digitaloceanspaces.com` | Region must still name the Space's region |
| Other S3 API clones | Vendor endpoint URL | Measured per vendor before relying on it |

## Browse surface

Roots are buckets (`bucket/<name>`); levels split on `/` into `prefix` and
`object` nodes. Node ids carry the full key so a restored tree re-reads, and
the join never double-slashes. `truncated` is the service's own `IsTruncated`.

## Operations

`tree`, `blob.read` (HeadObject), `blob.download` (GetObject stream),
`blob.upload` (PutObject, returns fresh meta), `blob.delete`. Deletes check
existence first: S3 answers 204 for a missing key, so the provider turns that
silence into a 404 (`RESOURCE_NOT_FOUND`) with its own sentence.

Capabilities: blob category, port 443, no SSH tunnel. Labels: Buckets/Objects.

## Preview

Range reads capped at 64 KiB (`S3_PREVIEW_LIMIT`). Text decodes as UTF-8;
`image/*` short-circuits to the image kind without reading a body; anything
that does not survive UTF-8 is `binary`, never mojibake in a text pane.

## Testing

`tests/integration/resources/s3-provider.test.ts` doubles the SDK with
`mock.module`; every answer is shaped from a live pass against MinIO
(`quay.io/minio/minio:latest`, measured 2026-09-20): roots answering Contents
+ CommonPrefixes together, missing keys answering 404 with message
"UnknownError" and NO code (the provider reads the status, not the code),
missing buckets answering `NoSuchBucket`, deletes answering 204 on absent
keys. Live re-verification: `docker compose -f resources-compose.yml up -d
minio minio-init`, then point a connection at `http://localhost:9000`.

## Known limitations

- ListBuckets caps at 1000 buckets with no continuation: accounts past that
  read short, and the page says so nowhere. Pathological in practice;
  documented instead of guessed around.
- Uploads through the route are base64-capped at 10 MiB
  (`BLOB_UPLOAD_LIMIT`); larger objects go through the SDK directly.
